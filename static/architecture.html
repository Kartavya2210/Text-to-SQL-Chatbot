System Design
Text-to-SQL Chatbot — Architecture
Request Flow — step by step
1
User types a question → Browser sends POST /query/stream with question + conversation history
2
FastAPI builds a prompt (rules + question) and calls qwen2.5-coder:7b via LangChain
3
Ollama returns generated SQL → FastAPI auto-corrects the table name if the model used a wrong one
4
FastAPI executes SQL on SQLite / PostgreSQL via SQLAlchemy; retries once with error-fix prompt on failure
5
Result rows are passed to qwen2.5:1.5b for plain-English narration — no SQL terms, numbers copied exactly
6
Same 1.5b model generates 3 follow-up suggestions based on the question and result columns
7
FastAPI emits a done SSE event — narration, SQL, rows, columns, suggestions, timing stats
8
Browser renders: narration text + data table + bar chart (if 2-col, ≤50 rows) + suggestion chips
